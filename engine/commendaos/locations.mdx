## Overview

The Locations API manages physical addresses where business entities operate — registered offices, principal places of business, warehouses, retail stores, factories, and more. Locations are used for registration threshold determination, compliance tracking, and employee management.

Commenda uses a single unified `locationType` vocabulary across CommendaOS and the Indirect Tax API. The same enum values describe a location whether you read it through the [CommendaOS Partner API](/engine/commendaos/partner-api/commenda-os-business-entities-id-locations-GET) or the [Indirect Tax Locations API](/engine/indirect-tax/locations/locations). When a location is created or updated through CommendaOS, Commenda automatically mirrors the change to the Indirect Tax service so nexus and registration logic stay in sync.

## Core endpoints

### List locations

Get all locations for a business entity.

```http
GET /business-entity/:businessEntityId/locations
```

**Path parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `businessEntityId` | integer | Unique identifier for the business entity |

**Response**

```json
{
  "locations": [
    {
      "id": "loc_abc123",
      "addressLine1": "123 Main Street",
      "addressLine2": "Suite 100",
      "city": "San Francisco",
      "state": "CA",
      "postalCode": "94105",
      "country": "US",
      "locationType": ["REGISTERED_OFFICE", "PRINCIPAL_PLACE_OF_BUSINESS"],
      "startDate": "2020-01-15",
      "endDate": null,
      "employeeCount": 25,
      "source": "COMMENDA",
      "sourceId": null
    }
  ],
  "count": 1
}
```

### Get location

Retrieve a single location by ID.

```http
GET /business-entity/:businessEntityId/locations/:locationId
```

**Path parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `businessEntityId` | integer | Business entity ID |
| `locationId` | string | Location ID |

**Response**

```json
{
  "id": "loc_abc123",
  "addressLine1": "123 Main Street",
  "addressLine2": "Suite 100",
  "city": "San Francisco",
  "state": "CA",
  "postalCode": "94105",
  "country": "US",
  "locationType": ["REGISTERED_OFFICE", "PRINCIPAL_PLACE_OF_BUSINESS"],
  "startDate": "2020-01-15",
  "endDate": null,
  "employeeCount": 25,
  "source": "COMMENDA",
  "sourceId": null
}
```

### Create location

Add a new location to a business entity.

```http
POST /business-entity/:businessEntityId/locations
```

**Path parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `businessEntityId` | integer | Business entity ID |

**Request body**

```json
{
  "addressLine1": "123 Main Street",
  "addressLine2": "Suite 100",
  "city": "San Francisco",
  "state": "CA",
  "postalCode": "94105",
  "country": "US",
  "locationType": ["PRINCIPAL_PLACE_OF_BUSINESS"],
  "startDate": "2020-01-15",
  "employeeCount": 25
}
```

**Response**

```json
{
  "location": {
    "id": "loc_abc123"
  }
}
```

### Update location

Update an existing location.

```http
POST /business-entity/:businessEntityId/locations/:locationId
```

**Path parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `businessEntityId` | integer | Business entity ID |
| `locationId` | string | Location ID |

**Request body**

```json
{
  "addressLine1": "456 Market Street",
  "addressLine2": "Floor 5",
  "city": "San Francisco",
  "state": "CA",
  "postalCode": "94103",
  "employeeCount": 30,
  "endDate": "2025-12-31"
}
```

**Response**

Returns `200 OK` on success.

### Delete location

Remove a location from a business entity.

```http
DELETE /business-entity/:businessEntityId/locations/:locationId
```

**Path parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `businessEntityId` | integer | Business entity ID |
| `locationId` | string | Location ID |

**Response**

Returns `204 No Content` on success.

## Location types

A single location can have multiple types — for example, the same address may be both a `REGISTERED_OFFICE` and a `PRINCIPAL_PLACE_OF_BUSINESS`. Commenda uses one unified `LocationType` enum across CommendaOS and the Indirect Tax API, so values mean the same thing in either surface.

| Type | Description | Use case |
|------|-------------|----------|
| `PRINCIPAL_PLACE_OF_BUSINESS` | Primary place of business operations | Main office or headquarters where day-to-day business is conducted |
| `REGISTERED_OFFICE` | Official legal address on file with authorities | Required for corporate filings, statutory mail, and registry records |
| `MAILING_ADDRESS` | Correspondence address | Where mail and notices are received |
| `HEADQUARTERS` | Main administrative office | Corporate HQ — distinct from the registered office in some jurisdictions |
| `BRANCH_OFFICE` | Secondary office location | Regional offices, satellite offices, foreign branches |
| `FACTORY` | Manufacturing facility | Production sites |
| `WAREHOUSE` | Inventory storage facility | Distribution centers, fulfillment warehouses operated by the business |
| `RETAIL_LOCATION` | Customer-facing retail location | Stores, showrooms, points of sale |
| `NATURAL_RESOURCE_SITE` | Natural resource extraction site | Mines, oil & gas wells, quarries |
| `REPRESENTATIVE_OFFICE` | Representative office in a foreign jurisdiction | Liaison offices that don't conduct revenue-generating activity |
| `CONSTRUCTION_SITE` | Active construction project site | Contracted construction work that may create permanent establishment |
| `THIRD_PARTY_FULFILLMENT` | Third-party fulfillment center | 3PL warehouses, FBA, marketplace fulfillment |
| `REMOTE_EMPLOYEE` | Location where remote employees work | Use `employeeCount` to record headcount at the location |
| `DEPENDENT_AGENT` | Agent who acts exclusively on behalf of the company | May trigger permanent establishment in some jurisdictions |
| `INDEPENDENT_AGENT` | Agent who acts on behalf of multiple companies | Generally does not create permanent establishment |
| `REGISTRATION` | Address linked to a tax registration | Used when a registration requires its own address record |
| `OTHER` | Other location type | Use only when no other type fits |

<Note>
  When `locationTypes` includes `REGISTERED_OFFICE` or `MAILING_ADDRESS`, `locationName` is required. When it includes `REMOTE_EMPLOYEE`, `employeeCount` is required.
</Note>

## Address fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `addressLine1` | string | Yes | Street address |
| `addressLine2` | string | No | Apartment, suite, unit, building, floor |
| `city` | string | Yes | City or locality |
| `state` | string | Conditional | State/province (required for US, Canada, India, Australia) |
| `postalCode` | string | Yes | ZIP/postal code |
| `country` | string | Yes | ISO 3166-1 alpha-2 country code |

## Employee tracking

Track employee count at each location for:
- Payroll tax threshold determination
- Workers' compensation requirements
- Local tax obligations
- Headcount reporting

Update `employeeCount` as staff levels change.

## Registration threshold determination

Use `startDate` to track when physical presence began in a jurisdiction. This is critical for:
- Indirect tax registration thresholds
- Income tax registration thresholds
- Payroll tax obligations
- Registration requirements

## Location sources

Locations can be created from multiple sources:

| Source | Description |
|--------|-------------|
| `COMMENDA` | Manually entered in CommendaOS |
| `GUSTO` | Synced from Gusto payroll |
| `RIPPLING` | Synced from Rippling HRIS |
| `JUSTWORKS` | Synced from Justworks |
| `DEEL` | Synced from Deel |

External locations include a `sourceId` for reference back to the originating system.

## Time periods

Track location validity with `startDate` and `endDate`:
- `startDate`: When the location became active (required)
- `endDate`: When the location was closed (optional, null for active locations)

This enables historical tracking of where entities operated over time.

## Indirect Tax sync

Locations created or updated through the CommendaOS Partner API are automatically mirrored to the Indirect Tax service for any business entity that has indirect tax enabled. Archiving a location in CommendaOS archives the corresponding record on the indirect-tax side. The mirror is best-effort: a sync failure does not block the CommendaOS write, but is logged so it can be re-run from the exposure page if needed.
