---
title: "Update a person"
openapi: "PATCH /partner/commenda-os/customers/{customerId}/persons/{personId}"
---

Partially update a reusable Commenda OS person for one of your customers.

Omitted fields are left unchanged. The response returns the updated person.

Use incorporation participant and document endpoints for incorporation-specific roles and documents.

## Residential address

Some incorporation requirements validate fields on the referenced person resource. For Singapore individual directors and shareholders, `participants.{participantId}.resource.residentialAddress` is satisfied in exactly one way: update the referenced person with the top-level `residentialAddress` field.

```json
{
  "residentialAddress": {
    "addressLine1": "1 Raffles Place",
    "city": "Singapore",
    "postalCode": "048616",
    "country": "SG"
  }
}
```

This stores the address on the person. Person read responses return it as the top-level `residentialAddress` field. It does not create a Commenda OS Location; Location resources are business-entity addresses, such as a partner-provided registered office address.

Do not send person `locations`, `locationTypes`, `CONTACT_ADDRESS`, or `resource.residentialAddress` for residential address requirements. Those fields are not the public Partner API contract for a person's residential address and are rejected.
