---
title: "Get incorporation validation"
openapi: "GET /partner/incorporation/{incorporationId}/validation"
---

Refreshes and returns validation for the full incorporation.

Use this endpoint when your UI needs the latest readiness state without fetching the full incorporation resource. The response includes `incorporationValidation` only.

## Validation issues

`missingRequirements` and `invalidRequirements` contain structured issue objects. Use `code`, `participantId`, and `documentKind` when they are present instead of parsing `path` with a regular expression.

For example, a missing participant document issue includes the participant and document kind directly:

```json
{
  "incorporationValidation": {
    "isComplete": false,
    "missingRequirements": [
      {
        "code": "PARTICIPANT_DOCUMENT_REQUIRED",
        "path": "participants.participant_123.documents.PASSPORT_SCAN",
        "message": "Passport scan is required for Directors",
        "participantId": "participant_123",
        "documentKind": "PASSPORT_SCAN"
      }
    ],
    "invalidRequirements": []
  }
}
```

Known issue codes currently include:

| Code | Meaning |
| --- | --- |
| `REQUIREMENT_MISSING` | A required incorporation-level field, participant, or grouped requirement has not been provided. |
| `REQUIREMENT_INVALID` | A submitted incorporation-level value does not satisfy validation. |
| `PARTICIPANT_REQUIREMENT_INVALID` | A participant or participant resource field is missing or invalid. |
| `PARTICIPANT_DOCUMENT_REQUIRED` | A required document slot for a participant has not been filled. |
| `SHAREHOLDER_REQUIREMENT_INVALID` | The shareholder participant requirement is not satisfied. |
| `SHAREHOLDER_OWNERSHIP_INVALID` | Shareholder ownership percentages are missing or do not satisfy the required total. |

Treat this list as extensible. Commenda may add new `code` values as requirements expand, so UIs should handle unknown codes gracefully.
